# 语义分析设计

## 1. 编译流程与输出

```text
testfile.txt → Lexer → tokens → Parser → AST → SemanticAnalyzer → SemanticResult
                 └────────────── DiagnosticEngine ────────────────┘
```

三个阶段共用同一个诊断器。词法或语法已经报错时也继续语义分析，适用于一个错误样例同时包含各类错误的要求。
正确程序仅生成 `symbol.txt`；错误程序仅生成 `error.txt`。
每次运行清除旧的另一类结果和旧阶段输出。语义模型不生成 LLVM IR、汇编或目标代码。

## 2. 栈式符号表

`SymbolTable` 使用 `Deque<Scope>` 保存活跃作用域，栈顶是当前作用域。
查找从栈顶向外逐层进行；重定义只检查栈顶，因而允许内层遮蔽外层名字。
`Scope` 用 `LinkedHashMap` 保持成功声明的先后顺序。
退出作用域只从活跃栈弹出，历史作用域和符号继续保存在列表里，供输出及后端查询。

规则如下：

- 初始化时建立全局作用域 1。每次进入新作用域，编号等于此前进入的作用域总数加 1。
- 每个函数建立一个作用域，参数先入表，再分析函数体声明，因此参数与最外层局部变量重名会报 b。
- 每个嵌套 Block（包括空块）建立新作用域。兄弟块得到不同编号。
- `switch (...) { CaseStmt... }` 不是 `Block` 产生式，自身不新建作用域；case 内的显式 Block 才新建。
- `main` 不入符号表，但它的函数体正常建立作用域。
- 声明依源码顺序进入表，不预声明后续函数；函数在分析自身函数体之前入表，允许自递归。
- 数组长度先分析；对象随后入表，再分析初值。声明初值中使用自身时可解析名字，但不能得到尚未确定的常量值。
- 重定义保留先前成功声明的符号，重复的函数仍按自己的返回类型和形参完整分析函数体。

输出遍历历史作用域，再遍历每个作用域中的成功声明，保证所有较小编号的符号排在较大编号之前。

`Symbol` 保存名字 token、作用域编号、符号种类、值类型、函数参数类型序列、数组长度和初值。
函数名与对象名共用名字空间。`typeName()` 负责生成作业要求的名字，表达式检查则只使用
`INT / CHAR / INT_ARRAY / CHAR_ARRAY / VOID`，const/static 不改变值类型。

`RuntimeLibrary` 单独保存运行时函数签名。`SymbolTable.lookup()` 查找完活跃的用户作用域后，
再查询此签名表。因此这些函数无需源码声明即可调用，但不会出现在 `scopes()` 和 `symbol.txt` 中。
运行时符号种类为 `RUNTIME_FUNCTION`，可通过 `isRuntimeFunction()` 与用户函数区分；
它们保留返回类型、形参类型及调用点绑定，不创建函数体作用域、活动记录或对象存储。
`put_str` 与 `put_string` 均接受一个 char[] 参数并返回 void，兼容文档和配套库的命名差异。

## 3. 活动记录与存储

每个函数（含 main）拥有一个 `ActivationRecord` 描述。分析函数时将其压入活动记录栈，
所有嵌套块的自动对象都分配到当前函数；函数结束时弹栈，描述保留在结果中。

| 内容 | 逻辑位置/大小 |
|---|---|
| 调用者链接 | 槽 0 |
| 返回地址 | 槽 1 |
| 非 void 函数返回值 | 槽 2 |
| 标量形参 | 1 槽，按参数声明顺序 |
| 数组形参 | 1 个地址槽，`indirect=true` |
| 自动标量变量/常量 | 1 槽 |
| 自动局部数组 | 数组长度对应的槽数 |

上述槽位是后端无关的布局描述，不是目标机字节偏移。
int 与 char 的物理大小、对齐、参数传递约定和返回值寄存器由后续后端决定。
当前不复用不同 Block 的局部槽位，不预分配临时表达式槽位。
数组长度因已有错误而未知时只保留占位布局，错误结果不应用于代码生成。

全局对象和 `static` 局部对象分配到独立的静态存储表。
同名静态对象也按各自的符号身份分配不同位置，避免不同函数/作用域之间冲突。
静态对象不进入函数帧，保存默认零初始化或显式初值元数据，供后续后端实现只初始化一次的语义。
本阶段没有运行时执行器，不实际创建递归调用时的多份栈帧。

`storageOf(symbol)` 可直接查询对象所在存储区、偏移、大小及是否间接访问。
槽位中的符号保留作用域编号，后续阶段能追溯局部对象的词法生存期。

## 4. 类型与常量求值

表达式通过显式后序工作栈处理，避免长左结合表达式产生线性的 Java 递归调用深度。
AST 节点使用 `IdentityHashMap` 索引，既避免 record 对子树递归计算 hashCode，也保留每个使用点的精确绑定。

二元运算要求两边为相同基本类型，数组和 void 不参加运算。
算术运算及一元 `+/-` 保留操作数类型，char 算术按模 256 回绕；
比较 `< <= > >= == !=` 与逻辑 `! && ||` 的结果统一为 int，值为 0 或 1。
这是 2026-10-22 按用户指定采用的结果类型约定，比较/逻辑运算前仍执行操作数类型检查。
一元运算要求基本类型；显式转换只接受 int/char。条件表达式允许任一基本类型。
数组下标和数组长度要求 int。数组访问得到元素类型，裸数组名保留数组类型以支持传参。
赋值要求标量左值和同类型右值，并独立检查常量修改。

`ExpressionInfo` 保存类型及可选常量值。未知值用 `null` 表示；错误类型用 `ERROR` 表示，
避免未定义名字等根本错误继续引发上层类型误报。
普通变量即便有字面量初值，也不会当作常量表达式的操作数；函数调用的结果也不进行编译期执行。

常量计算包含：

- int 运算、单目运算、比较与逻辑运算。
- char 每次运算及向 char 转换后取低 8 位，向 int 转换保留无符号数值。
- 字符常量的 `\n`、`\t`、`\r`、`\0`、`\\`、`\'` 转义。
- 常量数组的常量下标访问，包括未显式赋值但应补零的元素。
- 数组长度和初值中的显式类型转换。

`InitialValue` 只保存显式初值及补零标记，不按数组总长度分配宿主内存。
字符串先解释转义，再按对象长度截断或补零，不额外附加超出数组长度的终止符。
全局和 static 对象默认补零；普通未初始化局部对象保持未知。
运行时初值表达式也保持未知，原始表达式和它的类型仍保存在 AST/语义结果中。

文法保证不出现未规定错误形式。非恒定 ConstExp、非法数组长度、越界、除零、非零 main 返回值等
没有独立指定的作业错误码，不擅自增加错误类别；无法求值时保留未知值。

## 5. 错误检测与定位

| 错误码 | 检查位置 | 报错位置 |
|---|---|---|
| b | 对象、函数、形参定义 | 重复名字 token |
| c | LVal、函数调用 | 未定义名字 token |
| d | 函数调用 | 被调用的名字 token |
| e | 运算、赋值、初值、返回、调用、下标、switch、printf 等类型检查 | 相应运算符、表达式、名字或语句起始位置 |
| f | void 函数中带表达式的 return | return 所在行 |
| g | 非 void 函数体最后一项不是 return | 函数体右花括号所在行 |
| h | 常量赋值（包括数组元素） | 左值名字 token |
| l | printf 占位符与实参数量 | printf 所在行 |
| m | 非法 break/continue | 语句关键字所在行 |
| n | 同一 switch 内重复 case 数值或 default | 重复标签关键字所在行 |

函数实参数量不匹配时报告 d，不再用错位形参报告 e；所有实参自身仍会遍历。
printf 数量不匹配时报告 l，否则逐个匹配 `%d`→int、`%c`→char、`%s`→char[]。
函数末尾是否存在 return 按文法约定做结构检查，不做所有控制流路径的返回证明。
非 void 函数的裸 `return;` 存在返回语句，但返回类型是 void，因此报告 e。

循环与 switch 使用独立上下文栈。break 要求存在任一循环/switch，continue 要求存在循环；
因此位于 while 内部 switch 中的 continue 合法，单独 switch 中的 continue 非法。
每个 switch 单独维护 case 值集合及 default 标志，互不污染。

词法 a 与语法 i/j/k 的检查和恢复机制保持原样。
诊断器用 TreeMap 按行号汇总，遵循“每行至多一个错误”的测试约定。

## 6. 验证

测试只使用 JDK 17，不引入第三方库；`gradlew.bat check` 包含：

- `ParserTest`：38 项原有语法/AST/恢复回归，并更新评测入口的输出预期。
- `SemanticModelTest`：作用域遮蔽与恢复、编号不复用、帧内数组布局、静态对象隔离、紧凑初值。
- `SemanticAnalyzerTest`：101 项语义样例，覆盖 15 种输出类型、所有错误类别、错误恢复、绑定、存储元数据、运行时函数签名及比较/逻辑结果类型。
- `CompilerTest`：5 次真实启动 Compiler 的文件协议测试，包含两组官方输入输出，验证连续切换、旧文件清理和无 IR 输出。

语义样例包含同一文件内全部 a–n 错误、重定义函数内部错误、10000 个运算符的表达式、
十亿长度数组的紧凑元数据、char 回绕、字符串截断/补零及嵌套循环/switch。

原始 PDF 的逐项复核、已修复遗漏和结果类型约定的调整依据见 [semantic-audit.md](semantic-audit.md)。
